# 《MD3 Minecraft Launcher 实例下载与安装系统 V2.0》

**文档版本：2.0**
**目标：将现有实例下载/安装机制升级为稳定、可恢复、可感知、低操作成本的现代 Minecraft Launcher 安装系统**

---

# 1. 项目目标

现有启动器的实例安装流程应该从：

> 点击下载 → 下载文件 → 安装 → 启动

升级为：

> 选择实例 → 自动分析 → 显示安装方案 → 准备资源 → 并发下载 → 实时校验 → 自动修复 → 安装完成 → 自动配置 → 可直接启动

核心目标：

### 用户侧

* 不需要理解 Minecraft 的 `.json`
* 不需要理解 Library
* 不需要理解 Asset
* 不需要手动处理 Forge/Fabric/NeoForge
* 不需要手动检查 Java
* 下载失败可以继续
* 下载中可以暂停
* 可以取消
* 可以重新下载
* 可以修复损坏文件
* 可以看到真正的下载进度
* 可以看到“正在下载什么”
* 可以看到预计剩余时间
* 可以看到失败原因
* 安装完成后直接进入实例

### 后端

建立统一的：

```text
Instance Installation Engine
```

负责：

```text
版本解析
↓
安装计划生成
↓
资源依赖解析
↓
文件任务生成
↓
下载调度
↓
并发控制
↓
断点续传
↓
Hash 校验
↓
失败重试
↓
缓存复用
↓
安装
↓
完整性检查
↓
实例 Ready
```

# 3. 最重要的设计：安装状态机

不要再使用：

```text
downloading: true / false
```

这种简单状态。

应该使用严格的 State Machine。

```text
CREATED
   ↓
ANALYZING
   ↓
PLANNING
   ↓
PREPARING
   ↓
DOWNLOADING
   ↓
VERIFYING
   ↓
INSTALLING
   ↓
FINALIZING
   ↓
READY
```

异常：

```text
          ┌──────────────┐
          ↓              │
DOWNLOADING → PAUSED     │
          │              │
          ↓              │
       FAILED ───────────┘
          │
          ↓
       RETRYING
```

取消：

```text
任何状态
   ↓
CANCELLING
   ↓
CANCELLED
```

# 6. 下载任务系统

不要：

```text

   await download()
}
```

而应该建立 Download Queue。

例如：

```text
DownloadManager
        │
        ├── Worker 1
        ├── Worker 2
        ├── Worker 3
        ├── Worker 4
        ├── Worker 5
        └── Worker 6
```

默认：

```text
maxConcurrent = 6
```

允许用户设置：

```text
2
4
6
8
12
```

但要有最大限制。

# 8. 文件缓存系统

这是整个启动器非常重要的一部分。

不要：

```text
每一个实例重新下载 library
```

应该建立全局缓存：

```text
backend/data/minecraft/
```

例如：

```text
minecraft/
├─ versions/
├─ libraries/
├─ assets/
├─ cache/
└─ downloads/
```

实例：

```text
instances/
├─ instance-a/
│  └─ .minecraft/
│
├─ instance-b/
│  └─ .minecraft/
│
└─ instance-c/
   └─ .minecraft/
```

如果：

```text
instance-a
```

已经下载：

```text
lwjgl-3.4.1.jar
```

安装：

```text
instance-b
```

直接复用。

不要重新下载。

# 9. Hash 内容寻址

进一步升级。

缓存文件可以采用：

```text
SHA1
```

作为唯一标识。

例如：

```text
cache/
└─ sha1/
   ├─ ab/
   │  └─ ab123456...
   ├─ cd/
   │  └─ cd123456...
```

安装任务：

```text
需要 lwjgl-3.4.1

↓
计算目标 SHA1

↓
CacheManager.exists(hash)

↓
存在

↓
直接复用
```

这样可以极大减少重复下载。

# 11. 临时文件机制

禁止直接：

```text
lwjgl.jar
```

边下载边写。

应该：

```text
lwjgl.jar.download
```

下载完成：

```text
SHA1 verify
```

成功：

```text
lwjgl.jar.download
↓
rename
↓
lwjgl.jar
```

失败：

```text
删除 .download
```

这样可以防止损坏文件污染缓存。

# 12. 文件校验

下载完成后：

```text
expectedHash
        ↓

        ↓
compare
```

结果：

```text
MATCH
```

或者：

```text
MISMATCH
```

如果：

```text
MISMATCH
```

自动：

```text
delete
↓
retry
↓
redownload
↓
verify
```

最多：

```text
3 retries
```

# 13. 智能重试

不要简单：

```text
失败 → 立即重试
```

使用：

```text
1s
2s
4s
8s
```

Exponential Backoff。

例如：

```text
第一次失败
↓
等待 1 秒

第二次失败
↓
等待 2 秒

第三次失败
↓
等待 4 秒
```

如果服务器返回：

```text
404
```

不要重试。

如果：

```text
500
502
503
504
timeout
ECONNRESET
```

可以重试。

# 22. ETA 计算

使用滑动窗口，而不是简单：

```text
remaining / currentSpeed
```

建议：

```text
过去 5 秒平均速度
```

计算：

```text
ETA = remainingBytes / smoothedSpeed
```

速度变化时不会疯狂跳：

```text
1 min
↓
5 min
↓
30 sec
↓
4 min
```

# 23. 暂停下载

点击：

```text
暂停
```

状态：

```text
PAUSING
↓
PAUSED
```

必须：

* 停止新的任务
* 正在下载的任务安全终止
* 保留 `.download`
* 保存 downloaded bytes
* 保存 installation state

恢复：

```text
RESUMING
↓
DOWNLOADING
```

继续 Range。

# 33. Forge 特别处理

你当前的错误：

```text
Could not find .forge_patched_minecraft
```

说明你的 Forge 安装/启动链路存在问题。

所以安装器必须把：

```text
Forge installation
```

作为独立阶段：

```text
Preparing Forge
↓
Downloading Forge
↓
Preparing Minecraft
↓
Patching Minecraft
↓
Generating Forge metadata
↓
Verifying Forge installation
```

而不是简单把：

```text
forge jar
```

当成普通 Library。

# 42. 下载去重

核心逻辑：

```text
Task A → hash X
Task B → hash X
Task C → hash X
```

不要：

```text
3 downloads
```

而是：

```text
Download hash X
       ↓
    Cache
    ↙ ↓ ↘
 A   B   C
```

# 43. 文件锁

防止多个实例同时下载同一个文件。

例如：

```text
.lock
```

或者进程级：

```text
Map<hash, Promise>
```

如果：

```text
instance A
```

正在下载：

```text
lwjgl.jar
```

instance B 请求：

```text
lwjgl.jar
```

直接等待同一个 Promise。

## 你这个项目尤其要解决的一个问题

结合你前面贴出来的 Forge 报错，我建议**不要现在只修 `Could not find .forge_patched_minecraft` 这个错误然后继续堆功能**。

你现在实际上需要把：

> **“实例下载器”与“Minecraft/Forge 安装器”彻底解耦。**

否则以后加入：

```text
Vanilla
Fabric
Forge
NeoForge
整合包
Modrinth Modpack
CurseForge Modpack
```

你的代码会越来越乱。

正确架构应该是：

```text
Instance
   │
   └── InstallationPlan
           │
           ├── MinecraftProvider
           ├── LoaderProvider
           ├── LibraryProvider
           ├── AssetProvider
           └── ModpackProvider
                    │
                    ↓
              DownloadManager
                    │
                    ↓
                 Cache
```

这样以后你要做你之前计划的**“市场模块 + 整合包一键下载”**时，市场只需要生成一个 `InstallationPlan`，后面的下载、缓存、校验、断点续传、进度 UI 全部复用，不需要再写一套下载系统。

**这才是把你的实例系统真正提升一个档次的关键。**
